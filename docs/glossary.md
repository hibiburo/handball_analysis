# ユビキタス言語定義（用語集）

- バージョン: 0.1（初版ドラフト）
- 作成日: 2026-09-28
- ステータス: レビュー待ち
- 前提: [product-requirements.md](./product-requirements.md)、[functional-design.md](./functional-design.md)、[development-guidelines.md](./development-guidelines.md)（いずれも承認済み）

本書は、ドキュメント・画面の表示・コードで使う言葉の **正** とする。
他のドキュメントと食い違いがある場合は本書に合わせて修正する。

---

## 1. 基本の約束

| 約束 | 内容 |
|---|---|
| 左右の基準 | 左右はすべて **シューター（攻撃側）から見た向き** とする。動画の映り方と一致し、シューターに「コース1を狙え」とそのまま伝えられる |
| 分析の主語 | 分析対象は **相手チームのGK**。指標は GK を主語にして表す（「失点」「セーブ」「セーブ率」） |
| 「GK」の表記 | 画面・ドキュメントでは「GK」。コードでは略さず `goalkeeper` / `Goalkeeper` |
| 「シュート位置」と「ポジション」の区別 | **シュート位置** はシュートを打った場所（コート上のゾーン）。**ポジション** はシューターの役割（LB・CB など）。ポジションが LB の選手がセンターから打つこともあるため、別の項目として扱う |
| 表記の統一 | 数字は半角、「6m」「7m」「9m」は半角の m。割合は「31%」のように整数の % で表示する |

## 2. ドメイン用語

### 2.1 データの単位（エンティティ）

| 用語 | 英語（コード） | 定義 |
|---|---|---|
| GK（ゴールキーパー） | `Goalkeeper` | 分析対象となる相手チームのゴールキーパー。チーム名・名前・背番号・利き手を持つ |
| 試合 | `Match` | 1本のYouTube動画に対応する1試合。日付・大会名・対戦チーム・動画URLを持つ |
| 出場GK | `MatchGoalkeeper` | 試合とGKの紐づけ。途中交代を想定し、1試合に複数のGKを紐づけられる |
| シュート | `Shot` | 分析対象のGKに対して打たれた1本のシュートの記録。動画時刻と、シュート位置・コース・結果などを持つ |
| 設定 | `Settings` | アプリ全体の設定値。1件のみ存在する |

### 2.2 シュートの記録項目

| 用語 | 英語（コード） | 定義 | 必須 |
|---|---|---|---|
| 動画時刻 | `videoTime` | シュートの瞬間の、動画の再生位置（秒、小数第1位まで）。「記録する」を押したときの再生位置 | ○ |
| 前後半 | `half` | 前半 = `1`、後半 = `2` | − |
| 試合時間 | `gameMinute` | 試合の経過時間（分）。動画時刻とは別物 | − |
| 担当GK | `goalkeeperId` | そのシュートに対応したGK | ○ |
| シュート位置 | `zone` | シュートを打ったコート上のゾーン（3.1） | ○ |
| コース | `goalCell` | ボールがゴールのどこに来たか。3×3の9分割の番号（3.2） | 条件付き |
| シュート種別 | `shotType` | シュートの打ち方（3.3） | − |
| 結果 | `result` | シュートの結末（3.4） | ○ |
| GKの対応 | `goalkeeperAction` | セーブしたときに体のどこで止めたか（3.5） | − |
| シューターの利き手 | `shooterHand` | シュートを打った選手の利き手（3.6） | − |
| シューターのポジション | `shooterPosition` | シュートを打った選手の役割（3.7） | − |
| 数的状況 | `situation` | 攻撃側から見た人数の状況（3.8） | − |
| メモ | `memo` | 自由記述（500文字以内） | − |

### 2.3 指標

| 用語 | 英語（コード） | 定義 |
|---|---|---|
| シュート本数 | `shotCount` | 結果を問わない全シュートの数 |
| 枠内シュート | `onTargetShots` | 結果が「失点」または「セーブ」のシュート。GKが対応すべきシュート |
| 枠内シュート数 | `onTargetCount` | 枠内シュートの数 |
| 失点数 | `goalCount` | 結果が「失点」のシュート数 |
| セーブ数 | `saveCount` | 結果が「セーブ」のシュート数 |
| セーブ率 | `saveRate` | セーブ数 ÷ 枠内シュート数。枠内シュートが0本のときは算出しない（「−」と表示） |
| 失点率 | `goalRate` | 失点数 ÷ 枠内シュート数（＝ 1 − セーブ率） |
| 参考値 | `isLowSample` | 枠内シュート数が閾値（既定3本）未満で、割合の信頼性が低い値。斜線と「参考」ラベルで示す |
| 弱点 | − | 失点率が高いコース・シュート位置・条件。本アプリで見つけたいもの（コード上の名前は持たない） |

## 3. 列挙値

表示名は画面にそのまま表示する文言。コード値は保存データ・書き出しファイルに使う値で、**一度公開したら変更しない**（変更する場合は `schemaVersion` を上げて移行処理を書く）。

### 3.1 シュート位置（`zone`）

| コード値 | 表示名 | 定義 |
|---|---|---|
| `lw` | レフトウイング | 左サイドのウイングエリアからのシュート |
| `lb` | レフトバック | 9m付近の左側からのシュート |
| `cb` | センター | 9m付近の中央からのシュート |
| `rb` | ライトバック | 9m付近の右側からのシュート |
| `rw` | ライトウイング | 右サイドのウイングエリアからのシュート |
| `pivot_l` | 6m左 | 6mライン付近の左側からのシュート（ポスト・カットイン） |
| `pivot_c` | 6m中央 | 6mライン付近の中央からのシュート（ポスト・カットイン） |
| `pivot_r` | 6m右 | 6mライン付近の右側からのシュート（ポスト・カットイン） |
| `seven_m` | 7mスロー | 7mスロー（ペナルティスロー） |
| `fast_break` | 速攻 | 速攻（カウンター・ブレイクスルー）からのシュート。位置より速攻であることを優先して記録する |
| `long` | ロングシュート | 自陣やセンターライン付近からのシュート（GKが前に出ているときなど） |

- 左右はシューターから見た向き（1章）
- 速攻・7mスローは、打った場所よりも状況を優先して記録する

### 3.2 コース（`goalCell`）

ゴールを3×3に分けた番号で表示する。画面では「コース7」のように表す。

```
        シューターから見たゴール
┌─────────┬─────────┬─────────┐
│ コース1 │ コース2 │ コース3 │   上段
├─────────┼─────────┼─────────┤
│ コース4 │ コース5 │ コース6 │   中段
├─────────┼─────────┼─────────┤
│ コース7 │ コース8 │ コース9 │   下段
└─────────┴─────────┴─────────┘
   左         中央        右
```

| コード値 | 表示名 | 補足（位置） |
|---|---|---|
| `1` | コース1 | 左上 |
| `2` | コース2 | 中央上 |
| `3` | コース3 | 右上 |
| `4` | コース4 | 左中段 |
| `5` | コース5 | 中央 |
| `6` | コース6 | 右中段 |
| `7` | コース7 | 左下 |
| `8` | コース8 | 中央下 |
| `9` | コース9 | 右下 |

- 画面の表示は番号のみ。補足（位置）はツールチップや凡例で示す
- 「コース」はゴール上の場所だけを指す。コート上の場所は「シュート位置」と呼び、混同しない

### 3.3 シュート種別（`shotType`）

| コード値 | 表示名 | 定義 |
|---|---|---|
| `jump` | ジャンプ | ジャンプして空中で打つシュート |
| `step` | ステップ | 地面に足をつけたまま打つシュート（ステップシュート） |
| `running` | ランニング | 走りながら踏み切らずに打つシュート |
| `diving` | 倒れ込み | 倒れ込みながら打つシュート（主にウイング・6m） |
| `lob` | ループ | GKの頭上を越す山なりのシュート |
| `bounce` | バウンド | 床にバウンドさせるシュート |
| `spin` | スピン | 回転をかけて軌道を変えるシュート |
| `other` | その他 | 上記に当てはまらないシュート |

### 3.4 結果（`result`）

| コード値 | 表示名 | 定義 | 枠内シュート |
|---|---|---|---|
| `goal` | 失点 | ゴールに入った | ○ |
| `save` | セーブ | GKが止めた | ○ |
| `post` | ポスト・バー | ゴールポストまたはバーに当たり、入らなかった | − |
| `miss` | 枠外 | ゴールの枠を外れた | − |
| `blocked` | DFブロック | ディフェンダーに当たってゴールに届かなかった | − |

- 「失点」は分析対象GKから見た表記。シューター向けに説明するときも画面の表記は「失点」で統一する

### 3.5 GKの対応（`goalkeeperAction`）

結果が「セーブ」の場合のみ記録する。

| コード値 | 表示名 | 定義 |
|---|---|---|
| `hand` | 手 | 手・腕で止めた |
| `foot` | 足 | 足・脚で止めた |
| `body` | 体 | 胴体・頭で止めた |
| `none` | 反応なし | GKが反応できないまま、体に当たって止まった |

### 3.6 利き手（`handedness` / `shooterHand`）

| コード値 | 表示名 |
|---|---|
| `right` | 右 |
| `left` | 左 |
| `unknown` | 不明 |

### 3.7 ポジション（`shooterPosition`）

ポジションは英語の略称で表示する（シュート位置のカタカナ表記と区別するため）。

| コード値 | 表示名 | 正式名 |
|---|---|---|
| `LW` | LW | レフトウイング |
| `LB` | LB | レフトバック |
| `CB` | CB | センターバック |
| `RB` | RB | ライトバック |
| `RW` | RW | ライトウイング |
| `PV` | PV | ピヴォ（ポスト） |

### 3.8 数的状況（`situation`）

シュートを打った側（攻撃側）から見た人数の状況。

| コード値 | 表示名 | 定義 |
|---|---|---|
| `even` | 同数 | 攻撃側と守備側のコートプレーヤーが同数 |
| `power_play` | 数的優位 | 相手の退場、または7人攻撃（GKを外してコートプレーヤーを増やす）で攻撃側が多い |
| `short_handed` | 数的不利 | 味方の退場などで攻撃側が少ない |

## 4. 分析・操作の用語

| 用語 | 英語（コード） | 定義 |
|---|---|---|
| 記録 | `record` | 動画を見ながらシュートを1本ずつ入力すること |
| 絞り込み | `filter` | 条件を指定してシュートを選び出すこと。同じ項目の中は「または」、項目どうしは「かつ」で組み合わせる |
| 絞り込み条件 | `FilterCriteria` | 絞り込みに使う項目と値の組み合わせ。GKごとに保持する |
| ヒートマップ | `heatmap` | コースごとの指標を色の濃淡で表した図 |
| ゾーンマップ | `zoneMap` | シュート位置ごとの指標をコート図上に表した図 |
| クロス集計 | `crossTable` | 2つの項目を行と列にとり、組み合わせごとに指標を表した表 |
| シーン | `Scene` | 1本のシュートを動画で再生する単位。記録時刻の前後に余白をとる |
| 前余白・後余白 | `preSeconds` / `postSeconds` | シーン再生で記録時刻の前・後に含める秒数（既定3秒・2秒） |
| ハイライト（連続再生） | `highlight` / `Playlist` | 絞り込み結果のシーンを順に続けて再生すること |
| 合算 | `aggregate` | 同じGKの複数試合のシュートをまとめて集計すること |
| 書き出し | `export` | データをファイル（JSON / CSV）に保存すること |
| 取り込み | `import` | 書き出したJSONファイルを読み込んでデータに加えること |
| バックアップ | `backup` | 全データの書き出し。最終日時を `lastBackupAt` に記録する |
| 重複 | `conflict` | 取り込み時に、同じIDのデータがすでに存在すること。「上書き」か「スキップ」を選ぶ |

## 7. コード上の命名規則（用語に関するもの）

一般的な命名規則は development-guidelines.md 3章に従う。本章は用語の使い方に関する補足。

- **ゴールの「コース」は `goalCell`** とする。`course` は「コース（進路）」と紛らわしく、`zone` はシュート位置と衝突するため使わない
- **シュート位置は `zone`** とする。`position` はシューターのポジションを指すため使わない
- **失点は `goal`** とする。分析対象GKから見た「失点」と、シューターから見た「ゴール」は同じ事象なので、コードでは1つの値にまとめる
- **割合は `〜Rate`**（0〜1の小数）、**件数は `〜Count`** とする。% への変換は表示時のみ行う
- 列挙値の表示名は `〜Labels` という名前の `Record` にまとめ、`src/domain/enums.ts` に置く（例: `zoneLabels`, `shotResultLabels`）。画面で表示名を直接書かない
- 画面の文言にコード値（`fast_break` など）をそのまま表示しない

```ts
// 良い例
<span>{zoneLabels[shot.zone]}</span>

// 悪い例
<span>{shot.zone}</span>
<span>{shot.zone === 'lb' ? 'レフトバック' : '...'}</span>
```
