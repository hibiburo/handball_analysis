## 1. 目的

**「実際の試合動画1本で、相手GKのシュートを記録し、コース別の弱点を確かめられる」最小の状態を作る。**

入力の使い勝手と分析の見え方を早く実際の試合で試し、2回目以降の改善につなげる。

---

## 2. 今回の範囲

### 2.1 実装する機能

| PRD の機能 | 今回の範囲 |
|---|---|
| F1 試合管理 | すべて（登録・編集・削除、YouTube URL の解析と埋め込み可否の確認） |
| F2 GK管理 | すべて（登録・編集・削除、試合への紐づけ） |
| F3 動画再生 | すべて（再生・停止、±2秒・±5秒、再生速度） |
| F4 シュート記録 | すべて（全記録項目、入力検証 V1〜V7、記録後の自動再開、取り消し） |
| F5 シュート一覧・編集 | すべて（時系列一覧、タップでジャンプ、編集・削除、動画時刻の微調整） |
| F6 ヒートマップ | ゴール図のヒートマップ（セーブ率・失点率・本数の切り替え、参考値の表示） |
| F7 条件絞り込み集計 | 絞り込みのみ（全項目）。ヒートマップのセルをタップしての絞り込みを含む |
| F8 ハイライト再生 | シーン一覧からの **1シーンずつの再生** のみ |
| F9 複数試合合算 | すべて（GK単位の合算、試合単位で対象から外す） |
| F10 書き出し／取り込み | JSON のみ（全データ・GK単位・試合単位の書き出し、取り込み、重複時の上書き/スキップ） |

画面は SC1〜SC5、M1〜M3 をすべて作る。SC4 分析画面と M3 動画プレーヤーは上記の範囲に限る。

### 2.2 データを守るための機能（今回必須）

PWA を次回に回すため、Safari のデータ削除（architecture.md 3.2）への対策として次を今回入れる。

- バックアップ警告（最終バックアップから7日以上で警告、SC1 に表示）
- `navigator.storage.persist()` による永続化の要求
- 設定画面での保存容量の表示

### 2.3 開発基盤

- Vite + React + TypeScript + Tailwind CSS のプロジェクト作成（architecture.md 1章）
- ESLint（層の依存ルールの検査を含む）、Prettier、Vitest、Playwright の設定
- GitHub Actions の CI（lint・型チェック・単体テスト・ビルド・E2E）
- `vercel.json`（SPA の rewrites、セキュリティヘッダー）
- README に、開発の始め方と Vercel 連携の手順を書く

### 2.4 今回の範囲外（2回目以降）

| 機能 | 理由 |
|---|---|
| クロス集計（F7 の一部） | ヒートマップと絞り込みで基本の分析はできるため |
| 連続再生（F8 の一部） | 1シーンずつの再生で根拠映像は見せられるため |
| ゾーンマップ（シュート位置別の図） | 絞り込みでシュート位置別の傾向は確認できるため |
| CSV 書き出し（F10 の一部） | JSON でバックアップと共有はできるため |
| PWA（ホーム画面追加・オフライン表示） | 2.2 の対策で当面のデータ保護を行うため |
| キーボードショートカット（F11） | タブレットでの入力を優先するため |
| Vercel と GitHub の連携作業 | ブラウザでのログイン操作が必要なため、利用者が README の手順で行う |

## 4. 受け入れ条件

### 4.1 機能

PRD 7章の受け入れ条件のうち、US1〜US6、US8、US9 のものをすべて満たすこと。加えて次を満たすこと。

| # | 受け入れ条件 |
|---|---|
| AC1 | GKを登録 → 試合を登録（YouTube URL）→ 記録画面でシュートを記録 → 分析画面でヒートマップを確認、までを一通り操作できる |
| AC2 | 記録画面で、一時停止 → シュート位置 → コース → 結果 → 記録 の **5タップ** で1本を記録でき、記録後に再生が再開する |
| AC3 | 結果に応じて入力欄が切り替わる（functional-design.md 5.2 の V2〜V5） |
| AC4 | 保存直後に「元に戻す」を押すと、その記録が取り消される |
| AC5 | 分析画面で、ヒートマップの各コースにシュート数・失点数・セーブ率が表示され、枠内シュート3本未満のコースは参考値と分かる |
| AC6 | 絞り込み条件を変えるとヒートマップとシーン一覧が更新され、画面を開き直しても条件が復元される |
| AC7 | シーン一覧のシーンを押すと、動画プレーヤーが重ねて表示され、記録時刻の3秒前から2秒後まで再生される |
| AC8 | 全データを書き出したファイルを、データを消したブラウザで取り込むと、同じ内容が復元される |
| AC9 | 不正なファイルを取り込もうとするとエラーが表示され、既存データは変わらない |
| AC10 | 最終バックアップから7日以上たつと、GK一覧に警告が表示される |
| AC11 | 画面の表示名・用語が glossary.md と一致している |

### 4.2 品質

| # | 受け入れ条件 |
|---|---|
| QC1 | `npm run lint`、`npm run typecheck`、`npm run test`、`npm run build` がすべて成功する |
| QC2 | `domain/` の単体テストのカバレッジが 90% 以上 |
| QC3 | E2E テスト（AC1 の流れ、AC8 の書き出し → 取り込み）が Chromium と WebKit で成功する |
| QC4 | GitHub Actions の CI が成功する |
| QC5 | iPad 横向き相当（1024×768）と PC（1280×800）で、画面が崩れず操作できる |
| QC6 | 明るい表示とダーク表示の両方で、文字とヒートマップが判別できる |
| QC7 | 1GKあたり500本のテストデータで、絞り込みを変えてからヒートマップが更新されるまで1秒以内 |

## 5. 制約事項

- 永続的ドキュメント（docs/）の設計・規約に従う。設計の変更が必要になった場合は、実装前に docs/ の更新を提案して承認を得る
- 実際の YouTube への接続は手動確認のみとし、自動テストではプレーヤーをモックに差し替える
- 手動確認には、埋め込みが許可された公開の試合動画を使う（利用者が用意する）
- Vercel と GitHub の連携は利用者が行う。README に手順を書くところまでを今回の範囲とする
- データ保存は IndexedDB のスキーマバージョン1として作る。書き出しファイルの `schemaVersion` も 1 とする
